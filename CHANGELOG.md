- Phase 4 E2E suite (2026-08-07, issue #37): Playwright covering four critical journeys — browse/filter/detail, contact submit, contact rate-limit, and admin login→publish→logout→guard — in a new top-level `/e2e` package rather than inside `frontend/`, so Netlify's Phase 5 build never installs a browser-automation framework. - Phase 6 performance pass (2026-08-07, issue #51, PR #83): build budgets replaced with values that can actually fire (the stock `initial` budget was 500 kB warn against 284 kB of real output), a request waterfall removed from the landing route, layout shift eliminated by reserving the detail gallery's box, and LCP hints added to the first rendered image. `NgOptimizedImage` was evaluated against `@angular/common` source and deliberately **not** adopted — automatic `srcset` needs a CDN loader that cannot exist for arbitrary admin-pasted origins, preload injection is SSR-only, and the oversized-image assertion never runs without known intrinsic dimensions. Two findings surfaced during review: the LCP hint silently no-op'd when the newest project had no images, and `path: ''` without `pathMatch` prefix-matched every URL. Also documented a silent-failure trap worth remembering — an Angular `bundle` budget naming a chunk that does not exist is ignored entirely, no warning, exit 0

- Agent-termination handling documented (2026-08-08, PR #84): a dispatched agent that dies on an API/session limit should be **resumed** via `SendMessage` with its agent ID, which the tooling states preserves its context — not salvaged by hand. Three agents were lost this way on 2026-08-07 and all three were salvaged manually; one had died mid-mutation-test and left a deliberate defect in the working tree beneath a comment saying the opposite, which nearly shipped. New "When a dispatched agent dies mid-task" section in `CLAUDE.md`, cross-referenced from `docs/AGENT_WORKFLOW.md` (with the worktree-lifecycle consequence: a dead agent's worktree isn't free while a resume is still possible) and `docs/AUTONOMOUS_WORKFLOW.md`

The independent-session review is mandatory and has no fallback; the merge gate was also reworded to fail closed after a first draft ("every *available* review layer") would have passed when no layer ran at all

- Project date period (2026-08-08, issue #85): `startedOn` plus a nullable `completedOn`, closing a spec/model gap open since Phase 0. Null `completedOn` means **ongoing**. Built contract-first — contract, data model and ADR before any code — then backend, then frontend against the same settled shape. Stored at day precision, rendered month/year. Enforced by DTO validation and a table `CHECK`; see the ADR in `docs/DECISIONS.md`

- Backend correctness checklist added to `CLAUDE.md` (2026-08-09, PR #94): seven standing risks, each traced to a real bug that `mvn test` alone did not catch across Phases 1-2, framed as recurring hazards rather than history. Two claims in the source draft were corrected before committing — the phase attribution, and a "never log a credential even at DEBUG" rule that would have contradicted a deliberate decision in `ResendEmailClient`. Review then found the *same* contradiction one bullet later, in the config-validation item, and three invented mechanisms in the accompanying `docs/AGENT_WORKFLOW.md` worktree guidance; all corrected, and logged in `AGENT_LOG.md` as a recurring authorial habit of fabricating the *because* behind a real observation
- `docs/AGENT_WORKFLOW.md` worktree-cleanup guidance now distinguishes a husk nested inside the repo (silently reports the main checkout's state) from a sibling one (`fatal: not a git repository`), names parent-directory discovery as the actual mechanism rather than a dangling gitfile, and explains what a large foreign-work-tree diff actually means instead of dismissing it

- Stale-reference safeguard in `CLAUDE.md` (2026-08-09, PR #95): a path alone is not a reference, since this repo is worked through many simultaneous checkouts and none is reliably `main`. Provenance is a **commit plus a dirty flag** (`git rev-parse --short HEAD` and `git status --porcelain`), not a branch name — `git rev-parse --abbrev-ref HEAD` returns the literal string `HEAD` in the detached worktrees this project mandates for PR review, and a branch name says nothing about uncommitted edits on top. Machine-specific counts and layout moved to `docs/AGENT_WORKFLOW.md` as an explicitly perishable snapshot, so `CLAUDE.md` carries only what stays true
- Recorded that `git cherry` and patch-ids answer "is this *commit* present", not "is this *content* present" (2026-08-09) — two commits on `phase3/frontend-foundation` appeared stranded until the added lines were compared and found byte-identical to commits already in `main`

- Content rendering prepared for real portfolio copy (2026-08-09, issues #86 and #87): project cards show a bounded excerpt instead of the full description, and gallery images are no longer announced as "screenshots". The clamp is deliberately two limits — a TypeScript excerpt bounding the DOM payload plus a CSS `line-clamp` — because `overflow: hidden` hides text visually while leaving it in the accessibility tree. See `AGENT_LOG.md` 2026-08-09
- Image alt text now asserts only what the frontend can actually know — `"<title>, image 1 of 2"` for gallery images, and `alt=""` for the card thumbnail, which sits inside a link whose visible text is already the title and was making the link announce the title twice. Same WAI rule, opposite answers, applied per-image rather than by convention. This is the honest ceiling without per-image alt text in the data model; see the follow-up issue

- Top-level `README.md` now documents how the project is built, not just what it is (2026-08-09, issue #52, PR #98): contract-first development, worktree isolation and its limits, the coordinator/implementer/reviewer split, and five real cases of what the process caught — plus what it costs. The cold review of that PR found three overstatements in the section itself, including a claim that two implementation sessions "could not read each other's code" when they had run sequentially in one worktree separated only by a prompt instruction. All corrected, and the section now records its own correction rather than quietly editing it out. Also refreshes a Status section that still said Phase 4 was next

- Content seed for the five portfolio entries (2026-08-10, advances #49): a new top-level `/content-seed` — data file plus a dependency-free script applying it through the real HTTP API, not a Flyway migration, since content is not schema. Idempotent by title, issues no `DELETE` on a normal run, and guarded by the same fail-closed locality check the E2E suite uses. Verified end-to-end against Spring Boot and Postgres
- The seeded prose is reflowed from the draft's hard wrapping (2026-08-10): `docs/CONTENT_DRAFT.md` wraps at ~90 columns, and `white-space: pre-wrap` preserves single newlines, so all **78** would have rendered as forced breaks mid-paragraph at a fixed 92 characters regardless of viewport. Whitespace only — word sequences and character counts verified identical against the draft, and confirmed in the database with zero lone newlines surviving

- Two process rules added to `CLAUDE.md` (2026-08-10): commit each unit of work as it passes its own check rather than batching to the end; and a GitHub closing keyword fires from anywhere in a PR body, including prose denying it. Inline code neutralises a keyword, blockquoting does not, and `closingIssuesReferences` reads only the PR description. See `AGENT_LOG.md` 2026-08-10

- Dispatch model policy (2026-08-10): model defaults moved into `.claude/agents/*.md` frontmatter rather than depending on a dispatch remembering a parameter — no dispatch had ever passed one, so every agent inherited the session model. Cold reviews, and anything touching auth/concurrency/shared state/migrations, stay on the expensive model. Two attempts at a clean selection *test* failed against this project's own examples, so the rule is a narrow allowlist that errs expensive. Rationale in `docs/AGENT_WORKFLOW.md`

- SEO basics (2026-08-10, issue #50): static description, Open Graph and Twitter card tags in `index.html`, plus per-route descriptions set at runtime. The split rests on one fact — Googlebot executes JavaScript, social scrapers do not — so the static tags are what LinkedIn and Slack actually read. `robots.txt`/`sitemap.xml` ship with an RFC 2606 `.invalid` placeholder and the checklist item stays open pending the real domain. Prerendering deferred with recorded revisit conditions. Review then found a latent defect this work activated: an untorn-down request subscription, harmless while writing to component-local signals and harmful once writing to `document.head`. See the ADR in `docs/DECISIONS.md` and `AGENT_LOG.md` 2026-08-10

### Fixed

- Phase 6 backlog cleared (2026-08-17/18): fourteen issues, backend 90 tests to 100 and frontend 193 to 236. The public contact form now says what is wrong instead of nothing (#106); the error colour was failing WCAG AA at **2.87:1** on the dark canvas and is now flipped per scheme with computed ratios recorded (#116); `GET /tags` no longer offers filter values matching zero projects (#124); two violations on one field no longer collapse in `Object.fromEntries` before anything can render either (#114); `errorInterceptor` validates a problem body's `errors` at the wire boundary and toasts when entries are discarded, so a partly-unusable body cannot look fully explained (#117); `Project.required` now matches what the API actually sends, with the client regenerated in the same commit (#93); the validation key format two clients parse is documented, including the handler-prefixed parameter shape a probe turned up (#109, #133); the admin form drops a server verdict once the value it judged has changed, and takes its id from `paramMap` rather than a one-time snapshot (#111, #107); the rate limiter evicts stale keys without opening a hit-losing race (#78); the npm audit is at zero, lockfile-only (#90); the zoneless test convention is written where spec authors will meet it (#110); and the E2E suite finally has a fixture that can fail on the excerpt, the clamp and alt text (#99). See `AGENT_LOG.md` 2026-08-18

- Admin project form: a failed load no longer destroys the project on save (2026-08-16, issue #92, PR #105). A `getProject` that failed cleared the spinner and nothing else, so an edit form rendered empty, editable and saveable over a real record — and saving PUTs, which is full replacement, so every field was overwritten with blanks. Now gated in two independent places: the template renders an error state with Retry instead of the form, and `submit()` returns early, making the path unreachable rather than merely hidden. Underneath it, a second failure of the same shape took four rounds to close: the form rendered server validation errors only into slots keyed by field name, and `errorInterceptor` deliberately stays silent when a 400 carries field errors, so any unslotted key meant **Save did nothing and said nothing**. Row keys (`links[0].label`), then collection-level keys (the bare `links` key from `@Size(max = 10)`, reachable by filling eleven complete link rows — each row's label and url are `required`, so the rows must be filled before the request is sent at all), then an asymmetry inside the fix itself. Closed structurally rather than by enumeration — a form-level region renders any entry no slot claimed, with claimed-ness derived from the same rule the slots look up with — and verified at review time by an adversarial key sweep asserting each message renders exactly once. Note the first two were long-standing gaps inherited from the Phase 3 form rather than regressions; only the later two were introduced by the preceding round's fix. Also fixed en route: `track $index` with positional `formGroupName` made a removed row display the deleted row's data while the model held the survivor; a stale verdict could migrate onto the wrong row after a removal and again mid-save; the form's own validators rendered nothing at all. 115 tests to 156. Four cold reviews, each finding real defects. See `AGENT_LOG.md` 2026-08-15
